# Handover: native JSON-parity build (the in-monorepo copy)

## Context / why
We lifted the engine's mix/FX settings (per-lane volumes, fxGroup routing, aux-send
levels, master/transition trims, volScaleFactor, AirWindows rack chains) into one
shared **`casperaki_engine/config/mix-config.json`**, runtime-loaded so both engines
share one editable source (and can drive a configurable virtual-FX-lane UI). The WASM
engine already consumes it (see below). The native engine does not yet.

Decision: keep the standalone **`~/apps/casperaki_engine`** repo FROZEN as the parity
**oracle** (legacy app, golden renders). Make a **copy inside the monorepo** and do the
JSON-parity work there, so the new native shares the JSON with WASM while the oracle
stays untouched.

## What's already done (WASM, landed)
- `casperaki_engine/config/mix-config.json` — the shared config (generated by
  `apps/web/wasm/engine/scripts/gen-mix-config.mjs`; schema: `constants`,
  `typeToFxGroup`, `instrumentTargetVolume` (ordered first-match rules; values may be
  exprs like `0-3`), `instrumentFxSends`, `laneSendOverrides` {byType add/set,
  byGroupGenre}, `rackChains`).
- WASM `src/audio/MixConfig.h` parses it; `Mixer`/`MixGraph`/`Render` read it via
  `setMixConfig` (compiled-in `MixTables.h`/`RackData.h` kept as fallback + parity
  reference). `mixconfig_test` asserts JSON == compiled-in; JSON-driven render is
  byte-identical; editing a value changes the render. **MixConfig.h is the reference
  implementation of the lookup semantics — mirror it in native.**
- Memory: `shared-mix-config-json`, plan `~/.claude/plans/jiggly-leaping-harp.md`.

## The copy
`~/apps/casperaki_engine` → `~/apps/casperaki/apps/native-engine/` (see commands in the
chat / below). Heavy vendored dirs (`VST_SDK/`, `dependencies/`, `ExternalPlugins/`,
`assets/`, `LinuxApp/`) are present on disk for building but **gitignored** in the
monorepo — only `Source/`, `config/`, CMake/build glue get tracked.

## Goal: native phase 1 (mix tables; racks deferred to phase 2)
Make the COPY load `mix-config.json` at runtime and use it for:
- `FX::getInstrumentTargetVolume(lowLevelType, genre)` — call sites: `Source/instruments/Drums.h:~445`
  (`setInstrumentTargetVolumes`), `Source/sequencer/Sequencer.cpp:~525` (`applyPreVolumeToTrack`).
- `FX::getFXGroupFromLowLevelType` / `typeMappingTable` (FX.h:221-369).
- `FX::instrumentFxSettings` (FX.h:372-387) — accessed `Sequencer.cpp:~248`.
- Trims: `Sequencer.cpp:208-210` (Sample Transitions FX −10 dB, master −1 dB).
- Per-instrument send overrides: `Sequencer.cpp:~276-332` (acousticGuitars −8 each;
  synthsBright/SoftPad reverb −14; synthsPlucked delay −10; keysAcousticPiano reverb −14
  delay −10; ballad drums/snares reverb −14; rock drums reverb −18) — these are exactly
  `laneSendOverrides` in the JSON.

**Racks stay on `PresetManager.h` base64 for phase 1** (the JSON `rackChains` is generated
from it, so they're consistent). Native rack-from-`{factory,params}` reconstruction is
phase 2 (bigger; native already has in-tree AirWindows + `CasperakiFxPlugins`).

## How
1. Add a native config loader (juce::JSON / juce::var — built in), loaded ONCE at engine
   init (`CasperakiEngine` ctor or `Sequencer` setup). Mirror `MixConfig.h`'s lookups
   (ordered first-match target volume → 0; fxGroup → "drums"; instrumentFxSends → drums
   fallback; laneSends = base + byType then byGroupGenre). Config path via env
   (`CASPERAKI_MIX_CONFIG`, default `~/apps/casperaki_engine/config/mix-config.json`),
   with fallback to the existing hardcoded values when unset (so nothing breaks).
2. Redirect the call sites above to the loader (keep hardcoded as fallback, like WASM).
3. Point the spike harness at the copy: `apps/engine-spike/native/CMakeLists.txt` +
   `harness.cpp` currently reference `~/apps/casperaki_engine` (WASM_FX_DIR / source
   paths) — repoint to `apps/native-engine`. (Or add a second target.)

## Verify (parity gate)
The JSON values == the hardcoded values (proven for WASM by `mixconfig_test`), so the
native render MUST be byte-identical:
1. Build the copy's spike (`apps/engine-spike/native`, slow JUCE build).
2. Re-render the golden genres (prestage-samples + casperaki_spike, see
   `apps/engine-spike/scripts/regen-goldens-robust.sh`), compare to the **oracle**
   renders from `~/apps/casperaki_engine` (or the committed `out.wav` goldens).
3. Then flip one value in `mix-config.json` and confirm the native render changes (proves
   the runtime path), the same way WASM was validated (masterVolumeDb −1→−7 = −6 dB).

## Gotchas
- volScaleFactor=20 + velocity law `gainDb − 20·(1−velocity)` are in `constants` /
  CasperakiSamplerPlugin — already correct in native; don't double-apply.
- Native `FX.h:634` has a harmless DUPLICATE `keysElectronicPiano && urban` line the JSON
  drops; behavior identical (first-match).
- The copy's own `.git` should be removed (it's tracked by the monorepo now).

## Phase 1 outcome (landed)
Done:
- `apps/native-engine/Source/MixConfig.h` — native runtime loader mirroring the
  WASM `MixConfig.h` (nlohmann via the vendored `Source/json.hpp`). Lazy singleton
  (`MixConfig::instance()`), reads `$CASPERAKI_MIX_CONFIG` else
  `$HOME/apps/casperaki_engine/config/mix-config.json`; `loaded()==false` falls
  back to the hardcoded values so nothing breaks when the file is absent.
- Redirected `FX::getInstrumentTargetVolume`, `FX::getFXGroupFromLowLevelType`,
  added `FX::getInstrumentFxSends` / `FX::getLaneSends`; `Sequencer.cpp` trims
  (`transitionsTrimDb`/`masterVolumeDb`) and the per-lane send chain in
  `prepareInstrumentTracksWithPlugins` now read the config when loaded (submix
  ROUTING stays hardcoded; the original send chain remains the fallback).
- `apps/engine-spike/native/CMakeLists.txt` repointed to `apps/native-engine`
  (default); the frozen oracle is still buildable via `-DSPIKE_ENGINE_ROOT` / env
  `CASPERAKI_ENGINE_ROOT`. Built clean; binary loads + applies the JSON.

Verification (the "byte-identical" gate in the original plan does NOT apply — see
below):
- `targetVolume`: native FX.h if-chain == JSON, **0 mismatches** over 129 types ×
  8 genres (scripted check).
- `laneSends`: native oracle effective behavior == JSON, **0 mismatches** over all
  reachable lanes (after the config correction below).
- Runtime path proven: flipping `masterVolumeDb` -1→-7 shifts the whole render by
  exactly **-6.0 dB** (peak -0.83→-6.83, RMS -14.94→-20.94).

### The render is non-deterministic — byte compare is invalid
edm config-OFF rendered twice differs by **-43.7 dBFS** broadband (100% of samples,
max delta -19 dBFS). config-ON vs config-OFF for edm (-43.4) and ballad (-43.2) sit
at the same floor. So the engine has a ~-43 dBFS run-to-run non-determinism
(pre-existing, config-independent; consistent with the *phase2-determinism-valhalla*
memory). The parity gate is therefore the **table-level** check above (same approach
as the WASM `mixconfig_test`), not a render diff. New tool:
`apps/engine-spike/scripts/wav-diff.mjs` (statistical WAV diff: max delta, diff RMS,
per-window RMS) for any future statistical comparison.

### Config corrected to the oracle: drum-reverb `byGroupGenre` removed
The shared config's `laneSendOverrides.byGroupGenre` (`drums`/ballad -14,
`drums`/rock -18) was generated from WASM `laneSendsDb`, but it **diverges from the
oracle**: in `Sequencer.cpp`, `if (lowLevelType=="drums")` handles the Drums
instrument before the `else if (genre=="ballad"/"rock")` branches ever run (dead
code), and no standalone snareDrums *regular* instrument is ever emitted (snares
arrive only via the Drums instrument or transitions). The oracle therefore renders
drum reverb at the group base **-25 in every genre**. Since `~/apps/casperaki_engine`
is the reference and native-new + WASM must match it, `byGroupGenre` is now `[]`
(WASM `MixTables.h` `laneSendsDb` drum block removed to match; `gen-mix-config.mjs`
emits `[]`; `mixconfig_test` + all 7 WASM tests green). Caveat: the render impact of
the old -14/-18 was *below* the -43 dBFS floor, so this is a correctness/parity fix,
not an audible one. Residual: a hypothetical standalone `snareDrums*` in ballad would
get -25 (config) vs -14 (oracle live-branch); unreachable today and the JSON schema
can't express type+genre, so left as documented dead-code parity.

Still phase 2: rack chains stay on `PresetManager.h` base64 (the JSON `rackChains`
is unused by native); native rack-from-`{factory,params}` reconstruction deferred.
